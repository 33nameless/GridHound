# GridHound — исправление выбора объектов

База: репозиторий 33nameless/Detector, коммит 34e8b39.
Это исходники, не готовый установщик. Перед заменой сохрани резервную копию проекта.

## Какой архив взять

- **GridHound_Selection_Update.zip** — только изменённые/добавленные файлы с исходными относительными путями. Для твоего текущего проекта.
- **GridHound_Selection_Full.zip** — самостоятельная папка Detector с исходниками и двумя исходными ONNX-моделями. Без bin, obj, .vs, .git и локальных *.user. Можно распаковать отдельно и сравнить, не затрагивая рабочую копию.
- **GridHound_Selection.patch** — альтернативный вариант для git; НЕ применять после замены тех же файлов из zip.

## Установка локально (рекомендую для первой проверки)

1. Закрой запущенный GridHound и сохрани свой проект отдельно.
2. Распакуй Update.zip в папку, где лежит Detector.csproj, с заменой файлов. Папки Models, Services, ViewModels, Views и tests должны объединиться с существующими, не оказаться внутри лишней папки.
3. Либо распакуй Full.zip отдельно и открой Detector/Detector.csproj.
4. В Visual Studio используй установленный .NET 10 SDK с поддержкой WPF. Сделай «Пересобрать решение». Старую сборку из bin не запускай вместо новой.
5. Если структура локального кода отличается от коммита 34e8b39, не заменяй вслепую: сначала сравни изменения с patch.

## Загрузка на GitHub: Add files via upload

1. Сначала проверь сборку и поведение локально.
2. Открой корень своего репозитория → Add file → Upload files.
3. Перетащи содержимое Update.zip, сохраняя структуру папок. После загрузки проверь пути: например `ViewModels/MainViewModel.cs`, а не `GridHound_Selection_Update/ViewModels/MainViewModel.cs`.
4. Если браузер не переносит папки, открой соответствующую папку репозитория и загрузи файл туда; для новой tests/SelectionRegression создай правильный путь.
5. Внеси все изменённые файлы одной согласованной версией. Не загружай bin, obj, .vs, .git, *.user или каталоги SDK.
6. Напиши сообщение коммита, например `Fix immediate object selection and forward exports`, и нажми Commit changes.

## Какие исходники изменены

1. Models/Detection.cs — уведомления свойств, признаки внешнего вида и ключ выбранного объекта, обновление существующей строки.
2. Models/FrameData.cs — путь источника кадра.
3. Services/FramePump.cs — продолжение с текущего кадра, режим точности и различение отменённого завершения.
4. Services/HungarianAlgorithm.cs — полноценное прямоугольное назначение с несопоставленными объектами.
5. Services/KalmanFilter.cs — связь координат/размера со скоростью в матрице перехода.
6. Services/SelectionLogic.cs — взаимно однозначное сопоставление, приоритет ID, геометрия и внешний вид, кадр и координаты первоначального выбора.
7. Services/TrackerService.cs — прогнозное положение и цветовые признаки при сопоставлении, исправление возраста нового трека.
8. ViewModels/MainViewModel.cs — кэш кадра, мгновенная перерисовка, синхронизация, результаты и экспорты.
9. Views/MainWindow.xaml — Click вместо Checked/Unchecked, переключатель Плавность/Точность.
10. Views/MainWindow.xaml.cs — освобождение ресурсов при закрытии.
11. README.md и README-ИСПРАВЛЕНИЕ.md — раздел «Обновление 17».
12. tests/SelectionRegression — отдельный консольный набор регрессионных проверок; три файла, без стороннего тестового раннера.

## Проверка у тебя в Windows

Используй публичные/тестовые изображения, а не личные фотографии.

1. Фото: сразу после добавления, без Play, отметь одного человека. Все остальные рамки и подписи должны исчезнуть, но сами люди и фон остаются.
2. Отметь второго: рамки ровно у двоих. Сними первую галочку: рамка только у второго. ✖ и Esc возвращают все рамки.
3. Проверь режим выбора кликом: один клик выбирает одного, Ctrl+клик добавляет/убирает. Невыбранные остаются в списке DETECTIONS.
4. Нажми Play для фото. Выбор сохраняется; RESULTS содержит выбранные детекции, не «0» при успешном распознавании.
5. Видео: выбери объект на первом кадре до Play. Уже превью должно показать только его рамку. Play не должен вернуть чужие рамки.
6. Pause → поменять выбор → превью меняется без Resume. Play продолжает с текущего кадра.
7. Stop → поменять выбор → превью меняется. Play продолжает; после последнего кадра стартует сначала.
8. Во время проигрывания переключи галочки. Чужие рамки не должны возвращаться. В Плавности небольшое отставание рамки от объекта ожидаемо.
9. Переключи на Точность: каждый показанный кадр должен соответствовать своим детекциям. На CPU видео может идти медленнее.
10. Перекрой выбранного или дождись его выхода. Не должно появиться выделение всех объектов; в логе — потеря/возврат, когда удалось сопоставить. Одинаковая одежда и ч/б снижают надёжность.
11. Переключи источник: старый выбор сбрасывается. Старый кадр и результаты не должны возвращаться после фоновой обработки.
12. Проверь Conf, NMS, Only Person и Highlight на паузе. Изменение этих настроек может потребовать нового инференса; сама галочка — нет. Для контуров нужна seg-модель.
13. Выключи SORT: выбор на фото/паузе работает. На движущемся видео без ID геометрическое удержание менее устойчиво.
14. Выбери объект в середине видео. Frames/Video должны начинаться с кадра выбора, без кадров прошлого. Для отметок до выбора файлы не создаются.
15. Проверь Frames с несколькими редкими отметками, Video, CSV и JSON. В аннотациях — только выбранные; MP4/AVI открывается. Video не содержит звук, как и раньше.
16. Быстро выполни Play → Pause → Stop → смена файла → Play, затем закрой окно. Не должно быть зависания или возврата старого изображения.

Пришли скриншот фото после выбора, короткий результат проверки видео и журнал сборки, если есть ошибки. Особенно важны пункты 6, 8, 10, 14–16: они требуют настоящего WPF-окна и видеокодеков.

## Ограничения

Гистограмма — компактный признак цвета всего bbox, а не полноценное узнавание человека. Она чувствительна к фону, свету, ч/б и одинаковой одежде. Длительная пропажа/резкое движение могут потребовать повторного выбора. При старте с начала после конца видео выбор сохраняется, но успешное узнавание объекта на совершенно другой позиции первого кадра не гарантировано. Нейросетевой ReID не добавлялся.

RESULTS не восстанавливает детекции прошлых кадров задним числом. В Плавности сеть намеренно пропускает кадры; полный покадровый проход выполняют Frames/Video, а CSV/JSON сохраняют накопленные результаты.
