# Численная фикстура центрального ROI

road-roi-crop-detections.json — свежие CPU-обнаружения модели Assets/yolov8n.onnx на центральном участке предоставленного дорожного исходника.538 кадров,3840×2160,25fps; кроп x1300,y300,w1400,h950; вход640×480,letterbox114,RGB/255,порог0,10,NMS0,45 class-agnostic. Python/OpenCV/ONNX Runtime повторяет пред-/постобработку приложения, побитовое совпадение с Windows не заявляется. В файле координаты локальные для кропа. Фотографий/видеокадров в фикстуре нет.

Все538 дополнительных проходов выполнены заранее для повторного использования в разных расписаниях. Экономный режим приложения не делает538 дополнительных проходов при25fps: в плотном replay только108. Режим каждый обработанный кадр делает538. В Плавности число обработанных кадров зависит от производительности.

Appearance посчитан на исходных пикселях рамки, после добавления смещения кропа, по текущему алгоритму VM:24×48 BGR,64 histogram bins. Replay переносит его к результатам реальной C# RoiPolicy.MapCrop, затем объединяет реальные C# RoiPolicy.Merge и подаёт в реальные TrackerService/SelectionLogic. Обычные обнаружения берутся из прежнего road-baseline-detections.json.

Тесты фиксируют OFF167/229,экономный167/230,каждый кадр402/410 — последние принятые кадры двух выбранных машин при плотной обработке. Это не непрерывность на всех промежуточных кадрах, не новый инференс внутри теста, не Windows GUI и не замер FPS. Независимой ручной разметки всего видео нет. Синтетические проверки отдельно проверяют перевод полигонов маски, защиту границ кропа, NMS, частоту, сброс, повторный кадр и раздельные расписания экспорта/просмотра. Реальный нативный C# инференс/построение seg-полигонов в Linux не выполнялся.

Новые tests требуют предыдущих road-baseline-detections.json и ski-baseline-detections.json, уже имеющихся в последней рабочей версии репозитория.
